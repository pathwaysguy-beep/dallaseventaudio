# Images: serve what was already encoded

The repo has carried 284 WebP and 284 AVIF files at four widths since the image
pipeline ran, and nothing referenced any of them. Every page served the full
size JPEG. This wires them up.

Measured in a real browser across ten of the heaviest pages, loading each page
and scrolling to the bottom so the lazy images fire:

|  | before | after | saved |
|---|---|---|---|
| desktop, 1440px | 8.60 MB | 2.10 MB | **76%** |
| phone, 390px | 8.70 MB | 1.78 MB | **80%** |

`/gallery` goes from 2.36 MB to 0.25 MB. `/wedding-av-rental-dallas` from 1.24 MB
to 0.10 MB. `/dj-speaker-rental` from 0.90 MB to 0.07 MB.

**PowerShell**
```
Expand-Archive -Path $env:USERPROFILE\Downloads\dea-images.zip -DestinationPath $env:USERPROFILE\Downloads\dea-images -Force
Copy-Item "$env:USERPROFILE\Downloads\dea-images\*" -Destination C:\DEA\ -Recurse -Force

cd C:\DEA
python tools\sync_chrome.py --check
python tools\optimize_images.py --check
git add -A
git commit -m "images: serve the webp and avif that were already encoded, at the width the page paints"
git push
```

Both `--check` runs must report **0 drifted**.

## How it works

An `<img>` becomes a `<picture>` with an AVIF source, a WebP source and the
original as the fallback `<img>`, keeping its existing src, alt, width, height
and loading attributes untouched. A browser that understands neither format gets
exactly the file it got before. 63 of those.

A CSS background becomes `image-set()`, the same idea where there is no element
to wrap. 8 of those.

**The `sizes` attribute is measured, not guessed.** `tools/imgsizes.json` records
how wide every image is actually painted on every page at 1440 and at 390,
captured from a real render, so the browser is told the truth and picks the
smallest candidate that covers it. That file is regenerated by re-running the
measurement if the layout changes; the script falls back to `100vw` for anything
it has no measurement for, which over-fetches rather than under-fetches.

`optimize_images.py` is idempotent the way `sync_chrome.py` is, and `--check`
proves it. Run it after any page rebuild.

## Verified

- Zero new 404s. `/gallery` and `/our-work` still request some images that do not
  exist, but those are the empty photo slots and they were 404ing before this
  change. On `/our-work` the count actually drops from 22 to 16.
- No broken images introduced, no horizontal overflow, no script errors, at 1440
  and 390 across eight pages.
- Every JSON-LD block still parses, every `<picture>` is balanced, and
  `sync_chrome.py --check` reports 0 of 79 drifted.

## One thing worth knowing

`/monogram-projector` is the only page this does not help. Its ten images are
video poster frames rather than photographs, so no derivatives were ever made for
them. Encoding those is a separate small job.

And eight fully encoded photo sets are sitting in the repo that no page uses:
five monogram and projector shots, a corporate videographer frame, a ballroom
projector screen, and a band soundcheck with stage monitors. Those are candidates
for the empty slots when we do that pass.
